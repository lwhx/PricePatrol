# 电商价格监控实现计划

> 工作者：按当前用户明确授权直接执行，不再次请求计划批准。独立模块采用隔离文件范围的子任务；父代理负责数据/API/调度与最终集成。

目标：本地运行可用的多店铺HTTP价格监控Web应用，配套Server酱、Docker和GitHub镜像构建配置。
规格：`docs/功能方案.md`；新增确认：通知采用Server酱，先本地测试，用户随后上传GitHub构建镜像并部署Linux。
架构：Node.js/TypeScript/Fastify＋Vue3/Element Plus/AG Grid；SQLite使用Node内置node:sqlite（避免本机Node26与Docker Node24间原生依赖构建问题），直接参数化SQL代替原建议Drizzle；单实例队列＋独立Cookie jar。产品无演示数据。

## 约束

金额整数分、ID字符串、身份校验、凭据加密不回显；全局最多5请求；未知/陈旧价格不算正常。页面查询数据库，不因筛选/复制请求商家。Server酱无SendKey时清楚标未配置，不伪造发送成功。未安装Docker，不宣称本机镜像验证通过。

## 文件与接口

- `shared/contracts.ts`：前后端、collector约定。
- `server/src/{database,security,domain,query,export,worker,scheduler,app,main}.ts`：父代理。
- `server/src/collector/**`、`server/test/collector*.test.ts`：HTTP采集独立子任务。
- `web/**`：Vue应用独立子任务，不修改package/shared/server。
- `server/src/integrations/**`、`server/test/integrations*.test.ts`、`Dockerfile`、`compose.yaml`、`.github/**`、`README.md`：通知/登录辅助/部署子任务。
- `server/test/{domain,database,app,worker,export}.test.ts`：行为测试；真实本机账号HTTP单商品验收不进入测试夹具或版本库。

## 审查重点

1. 无SendKey/真实登录时不能输出虚假的成功状态。
2. 任务变更、账号会话更新和部分失败不能污染另一个店铺、旧运行报告或新价状态。
3. 全部筛选结果复制不能只包含当前页；预览/导出同快照，商品去重不吞SKU价格。
4. Node HTTP与先前Python探针不同，必须真实请求验证。
5. GitHub构建配置不等于Docker构建或Linux已测；凭据/本机数据绝不进入Git。
