# 电商价格监控：功能方案

状态：待评审设计，产品代码尚未实现。本文件是当前功能规格，取代旧《需求与设计草案》中冲突的内容。项目目录：`F:\Hermes\项目\电商价格监控`；部署目标：Linux Docker。外部报警通知最后实现，不阻塞数据、任务和预警记录功能。

## 1. 已确认目标与设计选择

已确认：多账号、一账号一店；导入Cookie或网页登录保存会话；HTTP获取商品ID、标题、SKU规格、后台标价、页面优惠前/优惠后价；采集结果写入数据库，页面查询数据库；同一店铺多个独立任务；全店/指定商品范围；任务折扣预警和商品ID/标题关键词白名单；折扣比较查询；勾选结果、自选字段、多种复制方式。

用户授权补充完善未想到的细节。下文标注的默认值为设计者建议，不伪称用户逐项指定。功能面向内部运营，商家商品价格写入不在范围内。

建议技术栈：Node.js 24 LTS＋TypeScript＋Fastify，Vue 3＋Element Plus＋AG Grid Community，SQLite WAL＋Drizzle，Docker Compose。后端SQL承担筛选/排序/分页，不依赖AG Grid商业版功能。复用现有JS解析/平台匹配模块，服务端重写HTTP请求层。

应用初版单实例、单调度所有者，无Redis前置依赖。登录辅助为独立Playwright/Chromium服务，按需创建服务端浏览器会话，日常采集不为每账号常驻浏览器。Cookie加密存储、按账号隔离；管理界面和远程登录入口需要认证，调试端口不能匿名公开。部署配置提供加密密钥，备份恢复须保留原密钥。

## 2. 证据和实现边界

本机天猫纯HTTP已实测：商品两页40个不重复ID，后台第一页20商品789SKU，3商品34SKU三价匹配。缺少MTOP签名令牌时能从服务端补取令牌再重新签名。浏览器只用于初次提供Cookie，采集由Python requests执行。

不能将此结果表述为淘宝、Linux出口、Node请求层、多账号或长期调度已通过。正式实现先分别验证淘宝/天猫及目标Linux出口；Node实现也要独立真实验收。MTOP令牌更新不等于商家会话失效后自动重新登录。

| 页面 | 功能 |

| 总览 | 店铺状态、任务进度、最近采集、预警、失败/陈旧数据数量 |
| 店铺账号 | 添加/更新Cookie、网页登录、实际店铺与平台核验、权限检测、停用、最近错误 |
| 商品价格 | 商品/SKU视图、数据库查询、筛选排序、勾选复制、导出、历史 |

| 预警记录 | 原因、SKU三价、处理状态、备注、关联作业和规则版本 |

商品详情用抽屉/模态窗，关闭后保留URL、筛选、选中与滚动位置；复杂任务编辑使用独立页面。列表保存列顺序、显示列、排序和页大小，列顺序提供明确拖拽入口。

## 4. 数据流与身份

1. 导入或登录后核验真实店铺身份、平台和商品权限，不能仅凭手填店名绑定，更不能用另一店Cookie覆盖原店身份。
2. 作业固定账号/店铺、范围、规则版本和白名单版本，异步结果写入前检查归属。
3. HTTP后台分页读取商品与SKU价，详情读取前台价格；按店铺＋商品ID＋SKU ID严格匹配。
4. 成功结果与进度逐批入库，来源、时间、缺失/失败原因独立保存。
5. 结束入库后生成本次预警记录；外部通知后续接入。
6. 页面、复制、导出读取数据库；明确点击“重新采集”才触发商家请求。

商品ID/SKU ID存字符串，金额存整数分。最新尝试状态、最后成功值与历史快照分开。失败时可展示上次成功价，但标明旧时间和本次失败，不把它当本次新价参与任务判断。后台独有SKU也保留，前台缺价注明；无独立SKU ID单列商品级记录，不伪造SKU 0或按名称配价。部分扫描不能据缺失判商品下架。

## 5. 查询、筛选与排序

### 查询范围和字段

- 店铺单选/多选，商品ID/SKU ID精确查找，标题/规格包含或不包含。
- 可粘贴多条商品ID或链接，提取ID、去重、显示无效项。
- 后台标价、优惠前、优惠后、优惠金额、实际折扣、后台标价与优惠前差额。
- 时间、成功/失败/缺价/陈旧、价格倒挂、预警状态、标签/备注。
- 可选择任务后查询该任务白名单命中项；不同任务白名单不能混成全局排除。
- 保存命名查询，如“低于8.5折”“自由岛价格”“本次失败”；保存的是条件和列设置，不是冻结数据。
- 条件组内选全部满足/任意满足；组间全部满足。初版一层分组，不实现无限嵌套编辑器。

### 折扣比较

折扣＝页面优惠后价÷后台SKU标价×10，支持 `<`、`≤`、`=`、`≠`、`≥`、`>`、区间。区间默认含端点，可设置开闭。输入支持8.5或8.5折，阈值大于0且不超过10，最多两位小数；实际数据可大于10折并展示倒挂。

比较使用整数分交叉相乘，不使用显示舍入。等于8.5折要求真实比值精确相等，8.5001折不匹配。界面折扣最多显示4位小数，悬浮提供更精确值及说明。缺价、后台零价、陈旧或来源不匹配为无法判断，不按0计算。

### 商品/SKU视图

- SKU视图每行一个规格，显示三价、折扣、来源时间和状态。
- 商品视图按店铺＋商品ID合并，显示SKU数、有效SKU最低/最高折扣、价格区间、命中/缺价/陈旧SKU数量。
- 商品查询默认任意SKU满足即命中；可切换所有SKU满足。存在无法判断SKU时，所有满足不能判真，否定规则也不能据缺价判正常。
- 显示总商品数、总SKU数、筛选命中数、选中数，不混淆商品数与SKU行数。
- 后端执行全量排序和分页，并添加店铺/商品/SKU身份作为稳定次级排序，避免跨页抖动。
- 默认查询最新视图；历史可选择一次执行或比较两次已结束执行，明确范围和时间。

## 6. 勾选、复制、导出

### 行范围与字段分开选择

范围支持：勾选行、当前页、全部筛选结果。勾选跨分页保留，显示总数；改变查询条件、视图或数据版本时清空旧选择并提示，避免复制隐藏旧行。“全部结果”查询后端完整匹配集，不能仅复制已加载页面。

复制窗口独立勾选字段：店铺、商品ID、标题、链接、SKU ID、完整规格/各规格列、三价、折扣、优惠金额、采集时间、状态与原因。可全选/清空、拖拽列顺序、选择表头、记住上次设置。

### 复制方式

| 方式 | 默认行为 |
| --- | --- |
| 仅商品ID | 按店铺＋商品ID去重，每行一个 |
| 仅商品标题 | 每商品一行，标题相同不合并不同商品 |
| ID＋标题 | Tab分隔，每商品一行 |
| Excel/飞书表格 | 自选列TSV，按当前商品/SKU视图输出 |
| 自定义文本 | 自选字段及分隔符，规范转义 |
| JSON | 结构化，保持ID/金额精度 |
| Markdown表格 | 转义竖线和换行，适合文档 |

包含SKU/规格/单SKU价格字段时按SKU行输出；仅商品字段可去重为商品行。不对不同SKU价格静默合并。商品视图勾选后展开复制，默认仅输出该商品中符合原SKU查询条件的行；可显式切换“所选商品的全部SKU”，切换后重新计算数量与预览。例如筛选低于8.5折时，默认不带出同商品9折的SKU。若只包含商品级条件而无SKU条件，则所有SKU都属于匹配集合。复制前显示前几行预览、范围、字段、总数与去重数量。

复制/导出开始时后端建立短时读取快照，固定查询、排序、数据版本、记录身份、列和数量。计数、预览与后续分块全部读取同一快照，不能混入采集过程中变化的行。

建议复制超过20000行或5MiB转为下载，不静默截断。剪贴板权限失败时显示手动复制文本。CSV/TSV/JSON下载沿用相同快照与字段选择。表格文本字段防公式注入；长ID保持字符串，提示Excel导入时按文本处理；纯ID复制不擅自加单引号。

## 7. 同店多个任务

每个任务独立保存名称、启用状态、店铺、范围、时间、规则组、白名单及历史。

- 全店任务每次重新发现当前在售商品；指定商品任务支持ID/链接批量添加和从查询结果勾选加入。
- 指定商品必须能在所选店后台核验；不属于该店/无法核验的ID列为异常，不以前台公开数据充数。
- 范围决定采哪些商品；白名单只决定哪些不报警，配置分开展示。
- 支持复制任务、立即运行、暂停/启用、停止/继续、重试失败项。复制任务默认暂停。
- 首版支持手动、每天、每周，默认Asia/Shanghai，显示下次运行时间；复杂cron留到后续。
- 同店不同采集作业排队运行，不抢用同一登录态；不同店也受全局最多5个在途请求约束。
- 同一任务已在队列/运行时再次手动点击返回现有作业，不重复创建。同一计划触发幂等。
- 运行期间再次到达计划时间，最多保留一个后续执行项；后续计划到期只更新该项的最近计划时间和合并次数，不无限追加。当前作业结束后执行这一个后续项。任务已有排队项且尚未运行时，新的计划合并至现有排队项。运行记录显示合并/延迟次数，暂停任务清除尚未开始的自动后续项。
- 第一版不同任务独立取新价，不跨执行暗中复用旧缓存。未来合并重叠任务须记录共享作业和各自规则版本。
- 修改规则影响下次执行；本次使用启动快照。删除/停用任务不抹掉价格历史与预警证据。
- 重启后未完成作业标为待恢复，重新核验会话，再允许继续。错过的计划每任务最多补跑一次，不重放所有停机计划。

示例：同店A任务全店低于8.5折，排除特价ID和“自由岛”；B任务仅指定自由岛商品，低于8折。两个任务可以并存，互不覆盖。

## 8. 规则与白名单

建议首版包含折扣比较、三价金额、优惠金额、后台标价与详情优惠前不一致、价格倒挂，支持一层全部/任意组合。查询与任务共用比较器。相对上次的复杂变化阈值先在历史比较展示，后续扩展。

按SKU判断，按商品去重统计；同SKU命中多条条件生成一条明细，保留全部触发原因。每种规则独立检验所需字段：优惠前缺失不会否决后台价和优惠后都有效的折扣判断。缺值不替换成0；组合采用真/假/未知三值逻辑。

白名单每任务独立：ID精确排除商品全部SKU，标题关键词按本次标题普通文本包含匹配。任一条命中即可排除；去首尾空白、拒绝空词，不默认正则。支持新增、停用、编辑、删除、备注和多条输入。排除仍采集入库、查询和保留历史。

编辑白名单可预览当前数据库命中的数量和部分商品，避免关键词范围过大。查询页选中商品后可加入某个任务白名单，返回新增/已存在/失败数量。历史执行保留原规则和排除原因，不随白名单修改重算。

## 9. 预警落库和处理

作业状态：排队、运行、成功、部分完成、失败、停止、等待登录/验证、待恢复。

采集结束入库后保存本次检查/排除/命中/无法判断/未访问数量与明细。部分成功仍检查本次有效新数据，但结果明确覆盖不完整；完全无法判断时不能报告全店正常。手动停止保留数据和进度，继续完成后才执行正常完成评估。

尚未终结的停止/待恢复作业可原作业继续，保留原规则快照；已有结束报告的成功/部分完成/失败作业不再被改写。“重试失败项”创建关联原作业的新执行，只采原作业失败项并沿用原规则/白名单版本，报告明确为重试范围；被删除或已不可用的账号直接报告不能重试。新执行产生独立快照和预警，原报告不变，不拿它作全店覆盖。希望按当前规则重查时使用“重新运行任务”，而非重试入口。

同次评估幂等，去重键含任务执行、店铺、商品、SKU和规则版本。每次执行保留报告，不因为前一天异常就隐藏当天异常。预警状态可待处理/已确认/已处理并填备注；处理不自动加白名单，也不屏蔽下一次触发。

外部通知最后实现。先提供数据库预警、总览计数、预警列表、任务结果和独立投递接口；不要求现在确定通知渠道。未来投递失败单独重试，不重跑采集。

## 10. 补充数据操作与维护

- 从查询结果批量加入指定任务、加入任务白名单、仅重采选中商品、重试失败项；执行前显示店铺与商品数。
- 标签/备注与采集价格证据分开，不手工覆盖原始价格。价格历史支持三价/折扣时间线及两次批次比较，标识缺价与覆盖范围。
- 建议历史保留180天可配置；预警关联证据保留至明确清理。清理显示影响范围，不随任务删除自动清空。
- 备份必须采用SQLite一致性备份，运行中不能只复制主db忽略WAL；恢复校验版本、先备份现状，密钥与数据库恢复一起说明。
- 配置/白名单/账号更新/清理操作保留审计记录，不记凭据明文。

实体包括账号/店铺、商品、SKU、作业与商品子任务、价格快照、最新尝试/最后成功值、监控任务、规则版本、白名单、保存查询、表格/复制偏好、预警事件/处理记录、投递记录。跨店查询合并展示但不合并身份。

## 11. 实现顺序与验收

1. 验证目标Linux出口及淘宝/天猫的Node HTTP请求层。
2. 多账号Cookie、身份核验、采集入库、进度与重启恢复。
3. 商品/SKU查询、折扣比较、排序分页、勾选行/字段、多格式复制导出。
4. 同店多任务、范围、调度、规则与白名单、预警落库。
5. 历史比较、备份、网页登录辅助、多会话隔离、Docker整体验收。
6. 最后实现外部通知。

验收包含：任务互不覆盖；白名单仍采集不预警；严格小于/等于/小数边界一致；失败旧价不当新价；跨页勾选及全部筛选结果复制；去重与字段粒度正确；预览和结果来自同一数据版本；长ID精度；重试不重复预警；容器替换后恢复数据和会话。无真实账号/出口时报告明确阻塞，不用模拟数据代替实测。

技术栈、历史保留和复制上限等属于建议默认值。初版不含多用户权限体系、无限条件嵌套、商家改价或复杂跨任务合并采集；外部通知延后不是当前阻塞项。
