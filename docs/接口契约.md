# 实现接口契约

所有 API 位于 `/api`。浏览器请求使用 `credentials:'include'`。非 2xx 响应为 JSON `{error:string}`；Zod 输入校验失败返回 400。类型定义见 `shared/contracts.ts`，TypeScript 相对导入保留 `.js` 后缀。

## 认证与店铺

- `GET /api/auth/status` → `{configured:boolean,authenticated:boolean}`。
- `POST /api/auth/setup {password}`：首次初始化，密码至少 10 字符，管理员 hash 持久化。
- `POST /api/auth/login {password}`；`POST /api/auth/logout`。
- 其余业务请求需要 session cookie。变更请求要求同源，或不带 Origin 的本机 CLI；拒绝浏览器跨域请求。
- `GET /api/overview` → `Overview`。
- `GET /api/shops` → `{shops:Shop[]}`。
- `POST /api/shops {name?,platform,cookies:string|CookieRecord[],userAgent?,appKey?}` → `{shop:Shop}`。服务端先核验实际卖家身份、平台与权限，再保存账号。
- `PATCH /api/shops/:id {name?,enabled?,cookies?,userAgent?,appKey?}` → `{shop}`。修改 Cookie 必须重新核验身份，不可覆盖为另一家店。
- `DELETE /api/shops/:id` → `{ok:true}`；有历史时停用。
- `POST /api/shops/:id/verify` → `{shop}`。
- `POST /api/shops/:id/collect {productIds?:string[]}` → `{run:Run}`，始终创建 `manual` 来源。

Cookie、SendKey 及浏览器账号凭据不在读取接口中返回。

## 采集任务

`CollectionTask` 保存店铺、名称、启用状态、采集范围、计划、版本、时间戳和下次运行时间。`/api/tasks` 只处理采集配置。

```json
{
  "shopId": "店铺ID",
  "name": "每日取价",
  "enabled": true,
  "scope": "all",
  "productIds": [],
  "schedule": {
    "kind": "daily",
    "time": "09:00",
    "days": [],
    "timezone": "Asia/Shanghai"
  }
}
```

- `GET /api/tasks` → `{tasks:CollectionTask[]}`。
- `POST /api/tasks CollectionTaskInput` → `{task:CollectionTask}`。
- `PATCH /api/tasks/:id` 接收采集输入的部分字段 → `{task}`，版本递增。
- `DELETE /api/tasks/:id` → `{ok:true}`。已保存的历史执行与价格证据保留。
- `POST /api/tasks/:id/run` → `{run:Run}`。无论任务是否配置计划，此入口始终手动采集，不执行预警。
- `POST /api/tasks/:id/duplicate` → `{task}`，副本默认停用。

`scope:'selected'` 要求至少一个商品 ID。商品/SKU ID 是 6–20 位数字字符串，商品 ID 数组最多 20000 项。计划支持 `manual`、`daily`、`weekly`；每周计划至少选一天。

## 预警任务

`AlertTask` 独立保存 `collectionTaskId`、派生的 `shopId`、名称、启用状态、检查范围、规则、白名单、通知开关、版本和时间戳。一个采集任务可关联多个预警任务。预警输入没有采集计划，也不要求客户端传 `shopId`。

```json
{
  "collectionTaskId": "关联的采集任务ID",
  "name": "低于八五折",
  "enabled": true,
  "scope": "all",
  "productIds": [],
  "rules": [{
    "mode": "all",
    "conditions": [{"field": "discount", "op": "lt", "value": "8.5"}]
  }],
  "whitelist": {"productIds": [], "titleKeywords": []},
  "notify": true
}
```

- `GET /api/alert-tasks` → `{tasks:AlertTask[]}`。
- `GET /api/alert-tasks/:id` → `{task:AlertTask}`。
- `POST /api/alert-tasks AlertTaskInput` → `{task:AlertTask}`。由关联采集任务派生店铺，初始版本为 1。
- `PATCH /api/alert-tasks/:id` 接收预警输入的部分字段 → `{task}`，版本递增。创建后禁止改变 `collectionTaskId` 或所属店铺。
- `DELETE /api/alert-tasks/:id` → `{ok:true}`。历史执行与已冻结快照继续保留。
- `POST /api/alert-tasks/:id/duplicate` → `{task}`。复制规则、范围、白名单、通知与采集绑定，创建独立 ID，版本为 1，默认停用。
- `POST /api/alert-tasks/:id/whitelist {productIds?:string[],titleKeywords?:string[]}` → `{task,added:number,existing:number}`。在事务中读取、合并、去重并保存，版本递增；任一输入或合并后总量无效则整体回滚。`added` 与 `existing` 合计统计商品 ID 和关键词条目，同一次输入中的重复项计入 `existing`。
- `POST /api/alert-tasks/:id/whitelist/preview {productIds?:string[],titleKeywords?:string[]}` → `{count:number,products:{productId,title}[]}`。查询当前商品，限制在该预警的店铺与检查范围内；按商品 ID 或标题关键词匹配，不附加预警价格条件。`count` 是完整匹配数，`products` 最多展示 20 项，不修改任务。

不存在或已删除的绑定返回 404；客户端指定不一致店铺、变更绑定或无效输入返回 400。`scope:'selected'` 至少需要一个商品 ID；至少一组规则，每组至少一个条件。白名单商品 ID 最多 20000 项；标题关键词最多 1000 项，每项去除首尾空白后 1–100 字符。

修改规则、范围、白名单与通知选择只影响之后创建的定时批次。价格查询和批量白名单入口使用预警任务上下文；批量添加采集商品仍操作 `/api/tasks`。

## 采集执行、预警执行与事件

### 触发与冻结边界

| 来源/操作 | `Run.trigger` | 预警处理 |
| --- | --- | --- |
| 店铺采集、任务立即采集、批量重采 | `manual` | 仅更新价格，不创建预警执行、不自动通知 |
| 失败项重试，包括定时批次的失败项重试 | `manual` | 新建手动批次，不创建预警执行 |
| 调度器到期创建的采集，最终 `success` | `scheduled` | 按入队时冻结的关联预警配置执行 |
| 调度器到期创建的采集，最终 `partial` | `scheduled` | 仅使用本批证据，预警执行标明覆盖不完整 |
| `failed`、`stopped`、`auth_required`、`recoverable` | 保留创建来源 | 不派发；恢复同一批次不改变来源 |
| 旧版历史采集 | `legacy` | 不因升级补评估或补通知 |

定时入队时冻结预警任务的范围、规则、白名单、通知开关与版本。暂停或删除预警任务不会修改已捕获的快照；停用或删除采集任务会清除其尚未开始的定时采集。手动与定时作业分别去重，不能把手动作业升级为定时来源。

只有 `scheduled` 且最终 `success` / `partial` 的采集可以创建 `AlertRun`。同一 `collectionRunId + alertTaskId` 最多一条预警执行。预警检查及通知队列独立于采集；通知失败不改变采集结果、不重新评估或重采。缺价、旧价或无法判断的 SKU 不代表价格正常。

### 执行接口

- `GET /api/runs` → `{runs:Run[]}`，最近最多 200 条。包含 `trigger` 与 `alertDispatchStatus`，不暴露内部任务快照。
- `POST /api/runs/:id/stop` → `{run}`。
- `POST /api/runs/:id/resume` → `{run}`，恢复同一批次并保留原来源。
- `POST /api/runs/:id/retry` → `{run}`，创建关联原批次的新手动采集。
- `GET /api/alert-runs?collectionRunId=&alertTaskId=` → `{runs:AlertRun[]}`，最近最多 200 条。两个可选过滤器同时传入时取交集；已提供的值必须非空。响应去除内部 `taskSnapshot`。
- `POST /api/alert-runs/:id/notify` → `{accepted:boolean,notificationStatus:string}`，明确重试该预警执行的汇总投递。

`AlertRun` 包含来源 `collectionRunId`、`alertTaskId`、店铺/任务名称、`status`（`queued | running | success | partial | failed`）、本次行数、检查/排除/命中/未知计数、`ruleVersion`、消息、开始/结束时间及独立通知状态。完整冻结配置保存在内部，不可通过接口改写。

### 预警事件

- `GET /api/alerts?state=&shopId=&runId=&alertRunId=` → `{alerts:Alert[]}`，最多 1000 条；过滤条件取交集。
- `PATCH /api/alerts/:id {state?,note?}` → `{alert}`；状态为 `pending | confirmed | resolved`，备注最多 2000 字符。

新事件的 `runId` 指向采集价格证据，`taskId` 指向预警任务，`alertRunId` 指向预警执行。多个预警任务可对同一批次的同一 SKU 分别产生事件。旧事件继续保留；缺少 `alertRunId` 的历史事件仍可按 `runId` 查询。

## 通知与设置

- `GET /api/settings` → `{notification:NotificationSettings,retentionDays:number,timezone:string}`。
- `PUT /api/settings {sendKey?:string,notificationEnabled?:boolean,retentionDays?:number}` → 同 GET。空 SendKey 明确清除，只返回 `hasSendKey`，不回显密钥。
- `POST /api/notifications/test` → `{accepted:true}` 或错误。此接口实际发送测试消息，只能由用户明确操作触发，不自动调用。
- 旧 `POST /api/runs/:id/notify` 返回 400，提示改用 `/api/alert-runs/:id/notify`，不能用于手动采集、旧版历史或整批多任务通知。

业务通知重新读取已存的预警执行，按 `alertRunId` 汇总，尊重冻结的 `taskSnapshot.notify`。来源必须是已成功/部分完成的定时采集，预警执行也必须成功/部分完成。全局通知需开启且已配置密钥；没有命中时标记 `skipped`，返回 `accepted:false`。通知正文给出采集批次、预警执行、规则版本和覆盖情况，最多列出前 60 条事件。

| `notificationStatus` | 含义与重试行为 |
| --- | --- |
| `pending` | 等待提交 |
| `disabled` | 全局通知或本批冻结的通知选择未开启；未满足开启条件时请求返回 400，冻结关闭的批次不能补发 |
| `not_configured` | 尚未配置 SendKey；配置后可明确重试 |
| `sending` | 正在提交；重复请求返回 409 |
| `accepted` | 服务已受理；重复请求返回 409，不代表最终送达 |
| `skipped` | 没有可发送的预警事件 |
| `failed` | 投递失败；不自动重发，可明确重试；中断时的在途投递应先人工核对 |

幂等状态先于全局配置检查：关闭通知或清空密钥不会把 `accepted` / `sending` 覆盖为其他状态。不存在的预警执行返回 404；来源、执行状态或配置不满足条件返回 400；重复发送返回 409；渠道投递失败返回 502。错误不暴露 SendKey、带密钥 URL、远端正文或异常 cause。通知更新仅写入 `AlertRun.notificationStatus` 及渠道错误设置，保持采集报告与价格证据不变。

集成模块 `server/src/integrations/serverchan.ts` 导出 `sendServerChan(sendKey:string,message:NotificationMessage,options?:{fetch?:typeof fetch}):Promise<{accepted:boolean;requestId?:string}>` 与 `serverChanEndpoint(sendKey):string`。支持 SCT 与 sctp 酱 3；只有 HTTP 成功且响应数字 `code === 0` 才视为服务受理。`notifyAlertRun(store,vault,input:AlertRunRecord,force=false)` 提供预警执行级通知；自动调用不会重试已有 `failed` 状态。

## 价格查询、导出与维护

- `POST /api/prices/query QueryInput` → `QueryResult`。`taskId` 表示预警任务上下文；其默认规则、检查范围及白名单作用于查询。显式 `groups:[]` 可不附加任务规则；`whitelistMode:'included'|'excluded'` 需要预警任务 ID。`runId` 仍表示采集批次，历史查询使用对应冻结配置。
- `GET /api/prices/history?shopId=&productId=&skuId=` → `{rows:PriceRow[]}`。
- `POST /api/prices/compare {leftRunId,rightRunId}` → `{rows:object[]}`，只比较同店已结束采集。
- `PATCH /api/prices/annotations {shopId,productIds:string[],tags?:string[],note?:string}` → `{updated:number}`。
- `POST /api/exports ExportInput` → `ExportResult`，返回固定快照 `content` 和 `preview`，超过复制上限推荐下载。
- `GET /api/exports/:token/download` → 固定快照文件。
- `GET /api/queries` → `{queries:{id,name,query:QueryInput}[]}`；`POST /api/queries {name,query}` → `{id,name,query}`；`DELETE /api/queries/:id` → `{ok:true}`。
- `POST /api/maintenance/backup` → 一致性 SQLite 备份下载。
- `POST /api/maintenance/cleanup {before:string}` → `{deleted:number}`；保护预警价格证据。

## 升级迁移

迁移在事务内将旧组合任务拆成原 ID 的采集任务，以及同 ID、关联该采集任务的默认预警任务。保持原店铺、范围、计划、规则、白名单、启用状态和通知选择；不同旧任务分别迁移，不合并。历史采集、价格和预警继续保留。重复打开数据库不重复创建；迁移失败回滚。

旧执行没有可信触发来源，标记 `legacy`，不创建历史预警执行，不补发历史通知。客户端迁移时需将规则、白名单和通知配置改写到 `/api/alert-tasks`，将通知重试改为预警执行 ID；`/api/tasks` 保留原 URL，仅保存采集配置。

## 登录辅助集成

`server/src/integrations/browser-login.ts` 导出 `BrowserLoginService`，构造参数为 `{dataDir:string}`。方法为 `create(platform)`、`screenshot(id)`、`action(id,{type:'click'|'type'|'press',x?,y?,text?,key?})`、`cookies(id)`、`close(id)`、`closeAll()`。

对应 API：`POST /api/login-sessions {platform}`；`GET /api/login-sessions/:id/screenshot` 返回 PNG；`POST /api/login-sessions/:id/action`；`POST /api/login-sessions/:id/complete {name?,platform}` 读取 Cookie 并核验身份后绑定店铺；`DELETE /api/login-sessions/:id`。

该模块运行本机或 Docker 内的 Playwright，提供真实截图、点击与输入。用户手动扫码和验证；没有浏览器时返回安装指引。
